Step 2 — Create the database module

The singleton pattern for the Postgres pool is important. In development, Next.js hot-reloads your server code on every change. Without a singleton, each reload creates a new pool and you'll exhaust Postgres's connection limit quickly. We store the pool on the global object so it survives module re-evaluation.

typescript
src/lib/db.ts 
import { Pool } from 'pg'

// Declare a global type so TypeScript doesn't complain about
// attaching things to the global object
declare global {
  var __pgPool: Pool | undefined
}

// Reuse the pool in dev (hot-reload safe), create fresh in prod
export const pool: Pool =
  global.__pgPool ??
  (global.__pgPool = new Pool({
    connectionString: process.env.DATABASE_URL,
    max: 10,                // max concurrent connections
    idleTimeoutMillis: 30000,
    connectionTimeoutMillis: 5000,
  }))

// Typed result row
export interface Job {
  id: number
  title: string
  company: string
  description: string
  skills: string[]
  created_at: Date
}

export async function getRecentJobs(limit: number): Promise<Job[]> {
  const { rows } = await pool.query<Job>(
    'SELECT id, title, company, description, skills, created_at FROM jobs ORDER BY created_at DESC LIMIT $1',
    [limit]
  )
  return rows
}

// Health check — useful for k8s liveness probes
export async function dbHealthCheck(): Promise<boolean> {
  try {
    await pool.query('SELECT 1')
    return true
  } catch {
    return false
  }
}

Vector Database — Pgvector

Phase 2 · ~1 hour

A vector database stores embeddings — floating-point arrays that capture semantic meaning. "Senior React developer" and "experienced front-end engineer" end up close together in embedding space even though they share no keywords.

We'll use pgvector, a Postgres extension, so we get vectors AND relational queries in one DB. No separate Pinecone/Weaviate account needed to get started.

Schema Setup

sql
migrations/001_init.sql 
-- Enable the pgvector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Jobs table with an embedding column
CREATE TABLE jobs (
  id          SERIAL PRIMARY KEY,
  title       TEXT NOT NULL,
  company     TEXT,
  description TEXT NOT NULL,
  skills      TEXT[],             -- extracted skill tags
  embedding   vector(1536),        -- OpenAI/Claude embedding dims
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- IVFFlat index for fast approximate nearest-neighbor search
-- lists=100 is a good starting point for <1M rows
CREATE INDEX ON jobs USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);

Generating and Storing Embeddings

✦

Claude doesn't have a native embeddings endpoint — use Voyage AI (Anthropic's recommended partner) or OpenAI's text-embedding-3-small. Both produce 1536-dim vectors compatible with this schema.

typescript
src/lib/embeddings.ts 
import OpenAI from 'openai'
import { pool } from './db'

const openai = new OpenAI()

export async function embedText(text: string): Promise<number[]> {
  const res = await openai.embeddings.create({
    model: 'text-embedding-3-small',
    input: text,
  })
  return res.data[0].embedding
}

export async function ingestJob(job: {
  title: string; company: string; description: string
}) {
  const embedding = await embedText(
    `${job.title} at ${job.company}: ${job.description}`
  )

  // pgvector expects the array as a bracket string: '[0.1,0.2,...]'
  await pool.query(
    `INSERT INTO jobs (title, company, description, embedding)
     VALUES ($1, $2, $3, $4::vector)`,
    [job.title, job.company, job.description, `[${embedding.join(',')}]`]
  )
}

export async function semanticSearch(
  query: string,
  limit = 5
) {
  const queryEmbedding = await embedText(query)
  const { rows } = await pool.query(
    `SELECT id, title, company, description,
            1 - (embedding <=> $1::vector) AS similarity
     FROM jobs
     ORDER BY embedding <=> $1::vector
     LIMIT $2`,
    [`[${queryEmbedding.join(',')}]`, limit]
  )
  return rows
}
⚠

The <=> operator is the pgvector cosine distance operator. Distance 0 = identical, distance 2 = opposite. We subtract from 1 to get similarity. The IVFFlat index won't be used until the table has at least lists * 39 rows (~3,900 for lists=100).

MCP Server — Custom Claude Tools

Phase 3 · ~45 min

The Model Context Protocol is an open standard (created by Anthropic) for connecting AI models to external tools and data sources. Instead of hardcoding tool logic into every LLM call, you run a separate MCP server process that exposes tools Claude can discover and call at runtime.

Think of it like a USB standard for AI tools — any Claude client that speaks MCP can plug into your server without custom glue code.

How it fits together

Claude (via AI SDK) │ │ speaks MCP (JSON-RPC over stdio / HTTP) ▼ Your MCP Server ← exposes tools: │ • search_jobs(query) → semantic search │ • get_skill_gaps(resume) → compare skills │ • get_job_detail(id) → fetch full posting ▼ Postgres + pgvector

Writing the MCP Server

typescript
src/mcp-server/index.ts 
import { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js'
import { StdioServerTransport } from '@modelcontextprotocol/sdk/server/stdio.js'
import { z } from 'zod'
import { semanticSearch } from '../lib/embeddings'
import { pool } from '../lib/db'

const server = new McpServer({
  name: 'skill-radar',
  version: '1.0.0',
})

// Tool 1: Semantic job search
server.tool(
  'search_jobs',
  'Search job postings semantically by skills or role description',
  { query: z.string(), limit: z.number().default(5) },
  async ({ query, limit }) => {
    const results = await semanticSearch(query, limit)
    return {
      content: [{ type: 'text', text: JSON.stringify(results, null, 2) }],
    }
  }
)

// Tool 2: Get skill gaps against a specific job
server.tool(
  'analyze_skill_gap',
  'Compare a list of candidate skills against a job posting',
  {
    job_id:         z.number(),
    candidate_skills: z.array(z.string()),
  },
  async ({ job_id, candidate_skills }) => {
    const { rows } = await pool.query(
      'SELECT title, skills FROM jobs WHERE id = $1', [job_id]
    )
    if (!rows[0]) return { content: [{ type: 'text', text: 'Job not found' }] }

    const required  = rows[0].skills as string[]
    const have    = required.filter(s => candidate_skills.includes(s))
    const missing = required.filter(s => !candidate_skills.includes(s))

    return {
      content: [{
        type: 'text',
        text: JSON.stringify({ job: rows[0].title, have, missing }),
      }],
    }
  }
)

const transport = new StdioServerTransport()
await server.connect(transport)
console.error('MCP server running on stdio')

Connecting the MCP Client (in Next.js)

typescript
src/lib/mcp-client.ts 
import { Client } from '@modelcontextprotocol/sdk/client/index.js'
import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js'

let client: Client | null = null

export async function getMcpClient() {
  if (client) return client

  const transport = new StdioClientTransport({
    command: 'npx',
    args: ['tsx', 'src/mcp-server/index.ts'],
  })

  client = new Client({ name: 'skill-radar-client', version: '1.0.0' })
  await client.connect(transport)
  return client
}

Vercel AI SDK — Streaming Chat

Phase 4 · ~1.5 hours

The Vercel AI SDK is a TypeScript library that handles the gnarly parts of working with LLMs: streaming responses over HTTP, multi-step tool-call loops, React state management, and error recovery. Without it you'd hand-roll Server-Sent Events, parse partial JSON deltas, and manage the tool-call ↔ tool-result message interleaving yourself. The SDK does all of that.

The SDK has two layers. The core (ai package) is framework-agnostic — it works in any Node.js server. The React layer (ai/react) adds hooks like useChat that wire streaming responses directly into component state.

How streaming works end-to-end

Understanding the data flow will save you hours of debugging. Here's what happens when the user sends a message:

1. useChat serialises messages → POST /api/chat (JSON body) 2. Route handler calls streamText() → opens connection to Claude API 3. Claude may respond with text, OR decide to call a tool first If tool call: 4a. SDK pauses stream → executes your tool's execute() function 4b. Tool result is appended to messages → Claude called again (a new "step") 4c. Claude now responds with text, using the tool's output 5. toDataStreamResponse() converts the stream → chunked HTTP response Each chunk is a text delta prefixed with a type code: 0:"Hello" ← text delta 9:{...} ← tool call a:{...} ← tool result 6. useChat on the client reads chunks → updates messages[] state live

The key insight is that maxSteps: 5 means Claude can call up to 5 tools in sequence within one user turn. Each tool call + result pair counts as one step.

Step 1 — The Route Handler

Create src/app/api/chat/route.ts. This is a standard Next.js Route Handler (App Router). The only special thing is export const runtime = 'nodejs' — without this, Next.js defaults to the Edge runtime which doesn't support Node.js APIs like the stdio transport our MCP client needs.

typescript
src/app/api/chat/route.ts 
import { streamText, tool } from 'ai'
import { anthropic } from '@ai-sdk/anthropic'
import { z } from 'zod'
import { getMcpClient } from '@/lib/mcp-client'

// Force Node.js runtime — required for MCP stdio transport
export const runtime = 'nodejs'

export async function POST(req: Request) {
  // useChat sends the full conversation history on every request.
  // This is how LLMs maintain context — there's no server-side session.
  const { messages } = await req.json()

  const mcp = await getMcpClient()

  const result = await streamText({
    model: anthropic('claude-sonnet-4-20250514'),

    // The system prompt shapes Claude's entire persona for this session.
    // Be explicit about which tools exist and when to use them.
    system: `You are a career coach specialising in tech roles. Help developers
understand their skill gaps relative to job postings in our database.

Workflow:
1. When a user describes their background or asks about a role, call search_jobs
   to find 3-5 relevant postings from the database.
2. For each interesting result, call analyze_skill_gap with the job_id and the
   candidate's skills (inferred from what they told you).
3. Summarise: what they already have, what's missing, and concrete next steps.

Be honest but encouraging. Prioritise actionable advice over exhaustive lists.`,

    messages,

    tools: {
      // Each tool needs: description (helps Claude decide when to use it),
      // parameters (Zod schema — validates Claude's output AND gives Claude
      // the shape it must fill in), and execute (runs server-side).

      search_jobs: tool({
        description: 'Semantically search the job postings database. Use natural language — "senior react engineer fintech" works better than keywords.',
        parameters: z.object({
          query: z.string().describe('Natural language description of the role or skills to search for'),
          limit: z.number().min(1).max(10).default(5).describe('Number of results to return'),
        }),
        async execute({ query, limit }) {
          // Bridge: AI SDK tool call → MCP server → pgvector search
          const res = await mcp.callTool({
            name: 'search_jobs',
            arguments: { query, limit },
          })
          // MCP returns content blocks; we only use the first text block
          return JSON.parse((res.content[0] as any).text)
        },
      }),

      analyze_skill_gap: tool({
        description: 'Compare a candidate\'s skills against a specific job posting to find matches and gaps.',
        parameters: z.object({
          job_id: z.number().describe('The job ID from a search_jobs result'),
          candidate_skills: z.array(z.string()).describe(
            'Skills the candidate has, inferred from their message. Use concise lowercase tags: ["react","typescript","docker"]'
          ),
        }),
        async execute({ job_id, candidate_skills }) {
          const res = await mcp.callTool({
            name: 'analyze_skill_gap',
            arguments: { job_id, candidate_skills },
          })
          return JSON.parse((res.content[0] as any).text)
        },
      }),
    },

    // maxSteps: how many tool-call rounds Claude can do in one user turn.
    // Steps: user message → (tool call → tool result) × N → final text reply
    // Set too low and Claude can't finish complex analysis; too high and costs spike.
    maxSteps: 5,

    // onStepFinish fires after each tool-call round — useful for logging
    onStepFinish({ stepType, toolCalls, toolResults, usage }) {
      console.log(`Step: ${stepType} | Tools called: ${toolCalls?.length ?? 0} | Tokens: ${usage?.totalTokens}`)
    },
  })

  // toDataStreamResponse() converts the AsyncIterable stream from streamText
  // into a chunked HTTP response the client's useChat hook understands.
  return result.toDataStreamResponse()
}

Step 2 — Build the ChatInterface component

Now the fun part. The useChat hook manages everything: sending messages, accumulating streamed text, and tracking the status of in-flight tool calls. Let's build it up piece by piece so you understand what each part does.

2a — What useChat gives you

typescript
understanding useChat's return values 
const {
  messages,           // Message[] — the full conversation history
                      //   message.role: 'user' | 'assistant'
                      //   message.content: string (the visible text)
                      //   message.toolInvocations: array of tool calls + results

  input,              // string — the controlled input value
  handleInputChange,  // React.ChangeEventHandler — wire to <input onChange>
  handleSubmit,       // React.FormEventHandler — wire to <form onSubmit>

  isLoading,          // boolean — true while waiting for any response chunk
  error,              // Error | undefined — set if the request fails
  stop,               // () => void — cancel the in-flight stream
  reload,             // () => void — re-send the last user message
  setMessages,        // manually override the messages array
} = useChat({ api: '/api/chat' })

2b — Understanding the message shape

Each item in messages[] has a toolInvocations array that grows in real time as Claude calls tools and results come back. Each invocation moves through three states you need to handle:

typescript
toolInvocations state progression 
// State 1: Claude has decided to call a tool but execute() hasn't run yet
{
  state: 'call',
  toolCallId: 'call_abc123',
  toolName: 'search_jobs',
  args: { query: 'senior react fintech', limit: 3 }
}

// State 2: execute() is running on the server — show a spinner
{
  state: 'partial-call',  // args may still be streaming in
  toolCallId: 'call_abc123',
  toolName: 'search_jobs',
  args: { query: 'senior react' }  // args incomplete
}

// State 3: execute() returned, result sent back to Claude
{
  state: 'result',
  toolCallId: 'call_abc123',
  toolName: 'search_jobs',
  args: { query: 'senior react fintech', limit: 3 },
  result: [
    { id: 7, title: 'Senior React Engineer', company: 'FinCo', similarity: 0.91 },
    // ...
  ]
}

// ── Sub-component: renders a single tool call + its result ──────────
function ToolCallPanel({ invocation }: { invocation: ToolInvocation }) {
  const [open, setOpen] = useState(false)

  // Map tool names to readable labels and colours
  const meta: Record<string, { label: string; colour: string }> = {
    search_jobs:       { label: '🔍 Searching jobs',       colour: '#00d4ff' },
    analyze_skill_gap: { label: '📊 Analysing skill gap',  colour: '#10b981' },
    get_trending_skills: { label: '📈 Fetching trends',    colour: '#f59e0b' },
  }
  const { label, colour } = meta[invocation.toolName] ?? {
    label: invocation.toolName, colour: '#6b7f96'
  }

  const isPending = invocation.state !== 'result'

  return (
    <div style={{
      border: `1px solid ${colour}33`,
      borderLeft: `3px solid ${colour}`,
      borderRadius: '0 6px 6px 0',
      background: 'rgba(0,0,0,0.2)',
      margin: '6px 0',
      fontSize: '12px',
      fontFamily: 'monospace',
    }}>
      {/* Header row — always visible */}
      <button
        onClick={() => !isPending && setOpen(o => !o)}
        style={{
          width: '100%', textAlign: 'left', padding: '8px 12px',
          background: 'none', border: 'none', cursor: isPending ? 'default' : 'pointer',
          display: 'flex', alignItems: 'center', gap: '8px', color: colour,
        }}
      >
        {isPending
          ? <span style={{ animation: 'spin 1s linear infinite' }}>⟳</span>
          : <span>{open ? '▾' : '▸'}</span>
        }
        <span>{label}</span>
        {isPending && <span style={{ color: '#4a6078', fontSize: '11px' }}>running...</span>}
        {!isPending && <span style={{ color: '#4a6078', fontSize: '11px', marginLeft: 'auto' }}>
          click to {open ? 'collapse' : 'expand'}
        </span>}
      </button>

      {/* Collapsed detail — inputs + result */}
      {open && invocation.state === 'result' && (
        <div style={{ padding: '0 12px 12px', borderTop: '1px solid #1a2332' }}>
          <p style={{ color: '#4a6078', margin: '8px 0 4px' }}>Input:</p>
          <pre style={{ color: '#7a9ab8', overflowX: 'auto', margin: 0 }}>

          <pre style={{ color: '#7a9ab8', overflowX: 'auto', margin: 0 }}>
            {JSON.stringify(invocation.result, null, 2)}
          </pre>
        </div>
      )}
    </div>
  )
}

          {message.content}

      )}
    </div>
  )
}

// ── Main component ──────────────────────────────────────────────────
export function ChatInterface() {
  const bottomRef = useRef<HTMLDivElement>(null)

  const {
    messages,
    input,
    handleInputChange,
    handleSubmit,
    isLoading,
    error,
    stop,
    reload,
  } = useChat({
    api: '/api/chat',

    // onError fires if the POST itself fails (network error, 5xx, etc.)
    // Distinguish from tool errors which come back as normal messages.
    onError(err) {
      console.error('Chat error:', err)
    },
  })

  // Auto-scroll to the newest message whenever messages update
  useEffect(() => {
    bottomRef.current?.scrollIntoView({ behavior: 'smooth' })
  }, [messages])

  return (
    <div style={{ display: 'flex', flexDirection: 'column', height: '100vh', maxWidth: '720px', margin: '0 auto' }}>

      {/* ── Message list ── */}
      <div style={{ flex: 1, overflowY: 'auto', padding: '24px 16px', display: 'flex', flexDirection: 'column', gap: '16px' }}>

        {messages.length === 0 && (
          <p style={{ color: '#4a6078', textAlign: 'center', marginTop: '80px' }}>
            Describe your skills or paste a job description to get started.
          </p>
        )}

        {messages.map(m => (
          <MessageBubble key={m.id} message={m} />
        ))}

        {/* Typing indicator — shown while stream is open but no text yet */}
        {isLoading && messages[messages.length - 1]?.role !== 'assistant' && (
          <div style={{ display: 'flex', gap: '4px', padding: '10px 14px' }}>
            {[0,1,2].map(i => (
              <span key={i} style={{
                width: '6px', height: '6px', borderRadius: '50%',
                background: '#4a6078',
                animation: `pulse 1.2s ease-in-out ${i * 0.2}s infinite`,
              }} />
            ))}
          </div>
        )}

        {/* Error state — network or API failure */}
        {error && (
          <div style={{ color: '#f87171', fontSize: '13px', padding: '8px' }}>
            Error: {error.message}.{' '}
            <button onClick={reload} style={{ color: '#00d4ff', background: 'none', border: 'none', cursor: 'pointer' }}>
              Retry
            </button>
          </div>
        )}

        <div ref={bottomRef} />
      </div>

      {/* ── Input bar ── */}
      <form
        onSubmit={handleSubmit}
        style={{ borderTop: '1px solid #1e2733', padding: '12px 16px', display: 'flex', gap: '8px' }}
      >
        <textarea
          value={input}
          onChange={handleInputChange}
          placeholder="I know React, TypeScript, and some Node.js — what am I missing for senior roles?"
          rows={2}
          style={{
            flex: 1, background: '#0f1318', border: '1px solid #1e2733',
            borderRadius: '6px', color: '#c9d4e0', padding: '8px 12px',
            resize: 'none', fontFamily: 'inherit', fontSize: '14px',
          }}
          // Submit on Enter, new line on Shift+Enter
          onKeyDown={e => {
            if (e.key === 'Enter' && !e.shiftKey) {
              e.preventDefault()
              handleSubmit(e as any)
            }
          }}
        />

        {isLoading
          ? <button type="button" onClick={stop}
              style={{ background: '#1e2733', border: 'none', borderRadius: '6px', padding: '0 16px', color: '#f87171', cursor: 'pointer' }}>
              Stop
            </button>
          : <button type="submit" disabled={!input.trim()}
              style={{ background: '#00d4ff', border: 'none', borderRadius: '6px', padding: '0 16px', color: '#000', cursor: 'pointer', fontWeight: '600', opacity: input.trim() ? 1 : 0.4 }}>
              Send
            </button>
        }
      </form>
    </div>
  )
}

Cloudflare Edge — Middleware & Workers

Phase 5 · ~45 min

Cloudflare Workers run JavaScript at ~300 global edge locations. In a Next.js context you'll encounter "edge" in two flavors: Next.js edge middleware (runs before your routes, on Vercel's edge) and Cloudflare Workers (a full serverless environment you deploy separately or via Cloudflare Pages).

Next.js Middleware for Auth + Rate Limiting

Create middleware.ts at the project root. It runs on Cloudflare's network (when deployed to Cloudflare Pages) or Vercel's edge — before your route handlers, globally, with near-zero cold start.

typescript
middleware.ts (project root) 
import { NextRequest, NextResponse } from 'next/server'

// This runs on the EDGE runtime — no Node.js APIs
export const config = {
  matcher: ['/api/:path*'],
}

// In-memory rate limiter (use Cloudflare KV or Upstash Redis in production)
const rateMap = new Map<string, { count: number; reset: number }>()

export function middleware(req: NextRequest) {
  const ip = req.headers.get('x-forwarded-for') ?? 'unknown'
  const now = Date.now()
  const window = 60_000   // 1 minute
  const limit = 20        // 20 req/min per IP

  const entry = rateMap.get(ip) ?? { count: 0, reset: now + window }

  if (now > entry.reset) {
    entry.count = 0
    entry.reset = now + window
  }

  entry.count++
  rateMap.set(ip, entry)

  if (entry.count > limit) {
    return NextResponse.json(
      { error: 'Rate limit exceeded' },
      {
        status: 429,
        headers: {
          'X-RateLimit-Limit':     String(limit),
          'X-RateLimit-Remaining': '0',
          'Retry-After':           String(Math.ceil((entry.reset - now) / 1000)),
        },
      }
    )
  }

  return NextResponse.next()
}

Docker — Containerize Everything

Phase 6 · ~30 min

Docker packages your app and its dependencies into a portable image. The key mental model: an image is a blueprint (a layered filesystem snapshot), a container is a running instance of that image.

Step 1 — Enable Next.js standalone output

The Dockerfile's runner stage copies .next/standalone — but this only exists if you tell Next.js to produce it. Add this to next.config.ts first, or the Docker build will fail silently with a missing file error.

typescript
next.config.ts 
import type { NextConfig } from 'next'

const config: NextConfig = {
  // Produces a self-contained output in .next/standalone/
  // The standalone folder includes only the files needed to run the server,
  // not node_modules — resulting in much smaller Docker images.
  output: 'standalone',

  // Disable the linting step during build (CI should run lint separately)
  eslint: { ignoreDuringBuilds: true },

  // Optional: avoid bundling pg (it has native bindings that confuse bundlers)
  serverExternalPackages: ['pg', 'pg-native'],
}

export default config

Step 2 — Write the Dockerfile

Multi-stage builds keep the final image small. The deps stage installs packages; the builder stage compiles TypeScript and builds Next.js; the runner stage is the only one that ends up in the final image — and it only contains what's needed to run, not build.

dockerfile
Dockerfile 
# ── Stage 1: Install dependencies ──────────────────────
FROM node:20-alpine AS deps
WORKDIR /app

# Install libc compat for native modules on alpine
RUN apk add --no-cache libc6-compat

COPY package*.json ./
RUN npm ci

# ── Stage 2: Build ──────────────────────────────────────
FROM node:20-alpine AS builder
WORKDIR /app

COPY --from=deps /app/node_modules ./node_modules
COPY . .

# Build env vars needed at build time (not runtime secrets)
ENV NEXT_TELEMETRY_DISABLED=1

RUN npm run build

# ── Stage 3: Production runner ──────────────────────────
FROM node:20-alpine AS runner
WORKDIR /app

ENV NODE_ENV=production
ENV NEXT_TELEMETRY_DISABLED=1

# Create a non-root user — important for security
RUN addgroup --system --gid 1001 nodejs
RUN adduser --system --uid 1001 nextjs

# Only the files the server actually needs to run
COPY --from=builder /app/public ./public
COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./
COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static

USER nextjs

EXPOSE 3000
ENV PORT=3000
ENV HOSTNAME="0.0.0.0"

HEALTHCHECK --interval=30s --timeout=5s --start-period=15s --retries=3 \
  CMD wget -qO- http://localhost:3000/api/health || exit 1

CMD ["node", "server.js"]

08

Wrap-Up & What's Next

You now have a full picture of how these technologies connect. Here's the full loop one more time, in plain English:

  1. A user opens the app — Cloudflare Edge middleware rate-limits and auth-checks the request before it ever touches your server.
  2. The Next.js App Router renders the home page as a React Server Component, querying Postgres directly for the job count.
  3. The user types their skills. The useChat hook (AI SDK) streams a POST to /api/chat.
  4. The route handler calls Claude via streamText. Claude decides to use the search_jobs tool.
  5. The AI SDK executes the tool — which calls your MCP Server over stdio.
  6. The MCP server runs a cosine similarity query against pgvector and returns the top matching jobs.
  7. Claude synthesizes the results and streams a skill-gap analysis back to the user in real time.
  8. All of this runs in Docker containers orchestrated by Kubernetes, with the HPA spinning up extra pods under load.

Extend the project

Add auth

Drop in Clerk or NextAuth. Use the Cloudflare middleware to validate JWTs at the edge — zero load on your origin for unauthenticated requests.

Persist chat history

Store conversation turns in Postgres. Pass them back into the AI SDK messages array. Now you have a stateful multi-session agent.

Add more MCP tools

Expose a GitHub tool that reads a user's repos and infers their skills automatically. MCP makes adding tools non-breaking.

CI/CD pipeline

GitHub Actions: test → docker build → push to ECR → kubectl rollout. Add a Helm chart to parameterize your k8s manifests.
